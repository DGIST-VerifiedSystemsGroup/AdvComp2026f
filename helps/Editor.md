# Editor Setup

> Generated by AI.

Any editor works. This page covers VS Code, which is what most people use — and what I can
actually help debug.

Finish [Setup.md](Setup.md) first. The editor talks to `ocaml-lsp-server`, which lives inside
your opam switch.

We assume that you have create a project (`dune init proj my_proj`).

---

## 1. Open the project from inside WSL

**This is the step people most often get wrong.** If you launch VS Code on Windows and open your
project through `\\wsl$\...`, the extension runs on the Windows side and cannot see your opam
switch. Nothing works, and the errors do not point at the real cause.

Install the **WSL** extension (`ms-vscode-remote.remote-wsl`), then open the project from a WSL
shell:

```bash
cd ~/path/to/project
code .
```

The bottom-left corner should read `WSL: Ubuntu-24.04`. If it does not, close the window and
reopen it this way.

Not on Windows? Skip this step.

## 2. Install the OCaml Platform extension

Search the marketplace for **OCaml Platform** (`ocamllabs.ocaml-platform`).

On WSL, make sure it installs into WSL rather than on Windows — the install button says so when
you are connected correctly.

## 3. Point it at your switch

`Ctrl+Shift+P` → search for `sandbox` → choose `opam` → `compilers`.

## 4. Check that it works

Run `dune build` once, then open any `.ml` file and hover over a function name. A type signature
should appear.

If nothing does, open the Output panel and select **OCaml Platform** from the dropdown. The log
usually names what is missing.

---

## What you get

**Hover for types.** Probably the most useful feature early on. Hover over anything — including
intermediate expressions — to see what the compiler inferred.

**Inline errors,** without waiting for a build.

**Go to definition** (`F12`) and **find references** (`Shift+F12`). You will be reading a codebase
you did not write; these are how you navigate it.

**Format on save.** Add to `.vscode/settings.json`:

```json
{
  "[ocaml]": {
    "editor.defaultFormatter": "ocamllabs.ocaml-platform",
    "editor.formatOnSave": true
  }
}
```

This needs an `.ocamlformat` file at the project root. An empty file is enough.

## Troubleshooting

**Hover shows nothing at all**
The language server is not running. Check the OCaml Platform output panel.

**The switch list is empty**
VS Code is running on Windows instead of inside WSL. See step 1.

**Nothing works until you build**
Expected. The server reads build artifacts, so a file that has never compiled has nothing to
report. Run `dune build` once.

**Worked yesterday, broken today**
You likely opened a terminal without the opam environment, or switched to a branch that does not
compile. `eval $(opam env)`, then `dune build`.

---

`.mll` and `.mly` files are not highlighted by this extension. Marketplace has community
extensions for both if it bothers you; nothing breaks without them.

Using Emacs or Vim? `ocaml-lsp-server` is already installed — point your LSP client at
`ocamllsp` and it works. Start the editor from a shell where `eval $(opam env)` has run.
